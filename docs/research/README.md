# Research and evidence

This page lists the evidence the project has, the evidence it still lacks and how the first research round is planned. There are no field findings yet. Every example in this repository comes from a simulation.

## What exists now

The only material about associations so far is an internal report in Turkish. It builds five possible association profiles around a nine-item questionnaire. This is design work, not data from five associations. The report has no field dates, response counts, participant quotes or signed letters, so no percentages or claims about adoption can be drawn from it.

## Planned method

The research lead contacts the associations. The first round aims at five associations and widens to eight if the pattern is still unclear. Each conversation starts with how the association handles handovers today and what happened at the last one. Scenarios are shown only after that.

A short questionnaire keeps the effort low. Anyone who wants to can add a follow-up conversation of 20 to 30 minutes with concrete examples. We ask what worked as well as what went wrong.

We do not ask for passwords or other credentials, member data, the web addresses of services or ethnicity.

## Before fieldwork

The project material refers to two versions of the questionnaire: an earlier six-question draft, which still has to be located, and the nine items in the simulation report. Before any responses are analysed, we record which version was used, with its language, wording and collection dates. Responses from different versions are combined only when the questions can be matched, and the matching is written down.

## Reporting

The anonymous summary (R02) will state the field dates, the number of usable responses, the number of distinct associations where this is known, the missing answers and one limitation of how participants were recruited.

It keeps four kinds of answer apart: past events, current arrangements, risks people imagine and handovers that went smoothly. Each association is counted once, even if several of its members respond. Results are given as counts out of a stated total, not as estimates for all associations. Rare combinations that could identify an association are left out. A code that can still be linked to a contact person is pseudonymous, not anonymous, until that link is deleted.

## When a need counts as shown

The same unsolved problem has to appear in at least three independent real accounts. Smooth handovers and associations with no recent handover are recorded separately and are not counted as failures. Interest in a tool is not, on its own, evidence that software is needed.

## The five simulated profiles

Each profile is linked to one of the [handover scenarios](../scenarios.md).

| Profile | Situation | Scenario |
|---|---|---|
| P1 | Nobody knows the recovery route for the domain or mailbox. | S1 |
| P2 | Nobody has confirmed whether a former social media or donation administrator still has access. | S2 |
| P3 | It is unclear who looks after the shared archive. | S3 |
| P4 | The current arrangement works and no new tool is wanted. | S4 |
| P5 | There has been no recent handover, only a concern about the next one. | None |

All five profiles are simulated, including what look like statements of interest. They must not be quoted as things participants said.
