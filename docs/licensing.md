# Licensing

No licence has been chosen yet. This page explains what a licence should make possible and which licences are proposed. Until the rights holders approve a choice in writing, nothing in this repository is licensed for reuse, and there is no LICENSE file.

## What a licence should make possible

An association should be able to:

- see how its handover records are processed
- run the register on infrastructure it chooses
- reuse and adapt the handover checklist
- keep its records if a maintainer stops supporting the project

For these aims, a documented export format and a reusable checklist matter as much as the source code.

## Proposed licences

| Material | Proposed licence | Reason |
|---|---|---|
| Original application code | AGPL-3.0-or-later | The register is a web application that associations can host themselves. Under this licence, people who use a modified version over a network can also get its source code. |
| Original documentation | CC BY 4.0 | Guides and checklists can be reused and adapted as long as the source is credited. |

These are proposals. They do not grant any rights.

## What a licence would not cover

Research notes, association records, contact lists, consent records and support letters are not documentation offered for reuse. No repository-wide licence notice applies to them, and they do not belong in this repository.

Material from third parties, such as fonts or icons, keeps its own licence. Its notice and attribution stay with the item.

## Before the first public release

- Identify the rights holders and confirm in writing what each of them grants.
- Add the approved licence texts, SPDX identifiers and a notice that explains what is excluded.
- List dependencies, fonts, icons and any copied material. Replace or remove anything whose origin is unclear.
- Record who maintains the project and how others can fork it or export their data.
